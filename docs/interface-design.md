# Interface design

Agent management is the visual reference for every built-in workspace. `public/design-system.css` is loaded after page styles and defines the shared type scale, controls, surfaces and states. Page styles retain their layout and responsive behavior.

| Component | Shared scale |
| --- | --- |
| Page title | 24px / 32px; 22px on narrow screens |
| Dialog title | 18px / 26px; 16px on narrow screens |
| Section heading | 14px / 22px |
| Interface text and form fields | 13px / 20px |
| Compact actions and navigation | 12px / 20px |
| Supporting text | 11px / 19px |
| Standard control | 36px tall, 8px corners |
| Compact action | 30px tall, 8px corners |
| Icon-only compact action | 30px square |
| Card / application shell | 10px / 14px corners |

Use existing theme variables for all colors. User-selected application, conversation and code fonts remain available. Coding surfaces retain the code font; Markdown and equations retain their document hierarchy.

The login form retains 16px mobile inputs to avoid browser focus zoom. Its desktop fields use the regular 13px interface scale. Native file-picker buttons use the same control shape as other forms.

Use `AgentHubIcons.svg(name)` for application controls and `AgentHubIcons.agent(id)` for Agent marks. The latter emits a safe, known `data-agent-icon` value for shared colors across the catalog, sidebar, session tabs and message headers. Button state changes should update the SVG and accessible label together.

Application controls use a 24px drawing grid, 1.75px rounded strokes and fixed 16–18px display sizes. Keep settings on a gear, runtime configuration on a settings panel, models on a cube, and the workbench on a four-tile mark so distinct destinations stay recognizable. Appearance uses a balanced half-light disc and the label “外观” on desktop; narrow layouts keep its 36px target and accessible name. Theme selection uses the same SVG check in Appearance and Settings, positioned over the preview without covering its caption.

Agent marks use selected, locally bundled [Lobe Icons](https://github.com/lobehub/lobe-icons) SVGs: OpenAI for Codex, Z.ai for ZCode, and the corresponding Claude, Gemini, DeepSeek, OpenCode, WorkBuddy and Cursor marks. Built-in execution and ordinary chat use a generic conversation mark. Keep native brand silhouettes intact, without decorative avatar tiles. Claude and DeepSeek retain their brand colors, ZCode uses the theme accent, and Gemini/WorkBuddy use the upstream multicolor SVGs. OpenAI/Codex and other monochrome brands follow the theme foreground; do not add a green tint to Codex. Session-list and tab glyphs are 14px, message-header glyphs 18px and catalog glyphs 22px. Uploaded images retain their own colors. The website uses a link mark; the favicon and initial HTML fallback match it. Use `capabilities` for the capability center and reserve `book` for skill documents.

`public/agent-identity.js` manages appearance overrides under `ah.identity.v1` in browser local storage. Users can change an Agent's default icon from its detail avatar, override one session from its More menu, and upload a workspace Logo from Appearance. The precedence is session override, Agent override, native brand. Clearing a session override follows the current Agent default. Existing DOM marks update in place, and same-origin browser tabs synchronize using the storage event. These are browser appearance preferences and are not synchronized through the backend or included in server backups.

PNG, JPG, WebP and standalone SVG uploads are limited to 2 MB, contained within a 128px square without distorting their aspect ratio, then saved as PNG. SVGs containing scripts, event handlers, foreign objects or external resources are rejected. Individual images, preference count and total stored size are bounded. Failed decoding or storage writes preserve the previous preference. The selected brand bundle is about 8.4 KB and adds no framework, CDN dependency, polling or animation.

Use `.fld` for fields, `.dialog-actions` for page-level actions, `.feature-panel` for tool sections, and `.feature-toolbar` for filters. A `.fld` directly inside a form grid has no outer margin: the grid owns its spacing. Keep custom native selects hidden and use the existing accessible select-button adapter.

Compact actions, including file-upload labels, use inline flex with centered icons and a 6px gap. Direct SVGs and enhanced `.ui-icon-slot` wrappers share a fixed 16px size in regular and compact buttons; icons must not shrink or depend on the text baseline. The low-specificity alignment defaults allow components to retain intentional grid or vertical layouts. Direct `.dialog-actions` buttons and upload labels use the same 36px control height and 13px text, while compact toolbar actions retain their 30px scale. Keep file inputs and legacy glyph spans hidden so they do not take up a flex slot.

Check the page frame, scrolling content, long labels, empty/error states, keyboard focus and read-only behavior. Verify compact and regular controls separately. Responsive acceptance uses the actual browser UI through CUA; screenshots and computed control measurements are evidence, while syntax and CSS structure checks provide supporting coverage.

Styling changes require a page reload. Backend activation is tracked separately when a previous feature introduces new API routes.

## Card order

Agent choices, Agent overview cards, environment lists, provider cards, model
rows, project cards and toolbox cards expose a subtle drag handle that becomes
clearer on hover or keyboard focus. Touch devices keep the handle visible. Focus the handle and use
**Alt + arrow keys** to reorder without dragging; **Escape** cancels an active
drag.

Agent order is saved through the Agent preferences API and reused by the new
task chooser, Agent management, environment views and sidebar. Other card order
is a browser preference. Filtering preserves the positions of hidden entries.
Reordering never enables an unavailable Agent, selects a model, sends a message,
changes a permission or starts a task. A failed save restores the displayed
order.
